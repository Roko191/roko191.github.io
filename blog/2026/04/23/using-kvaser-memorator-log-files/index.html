Using Kvaser Memorator log files

2026-04-23 — Roko191

We use Kvaser Memorator devices on our Formula Student car and needed a way to extract logged data and use it in our custom telemetry application. When thinking through the implementation, two core questions came up:

  • How can data be extracted from the SD card?
  • How do we efficiently parse potentially large log files containing a high volume of messages?

The first question is straightforward - we can use the Kvaser CANlib SDK to read data off the SD card. The second turned out to be more involved, and led to designing a KmeReader class that encapsulates all the required functionality and is later used by our WebSocket server.

How Kvaser Memorator Works

Kvaser Memorator stores data on an SD card in the .kmf format. The card is first formatted to FAT32, and Kvaser uses a multi-file layout that fills nearly the entire card. Each KMF file is approximately 1 GB, meaning a 16 GB card will contain 16 KMF files, with a small portion reserved for a database file used to manage them.

Because of this layout, a KMF file cannot stand on its own. When calling openKmf, the library looks for the accompanying database file and returns an error if it is not found. This is why you need to point to the first KMF file rather than an arbitrary one.

KMF files can be converted to the .kme format, which is self-contained. Once converted and stored on disk, the KME file can be read independently — no SD card or database file required. This also brings a significant storage benefit: if only 1 GB of data was logged on a 16 GB card, the resulting KME file will be approximately 1 GB rather than requiring the full 16 GB to be preserved. This makes the KME format faster, cleaner, and more practical for use in a telemetry application.

Known issues

If you are running a newer version of libxml2, the SDK may fail to compile due to a breaking API change. In newer versions of the library, the previously public _xmlBuffer fields use and content are now accessed through xmlBufferLength() and xmlBufferContent() respectively. The following sed commands apply the necessary fix:

1
2
3
4

cd kvlibsdk/kvamemolibxml
sed -i 's/-Werror//g' Makefile
sed -i 's/xml_writer_buf->use/xmlBufferLength(xml_writer_buf)/g' kvaMemoLibXML.cpp
sed -i 's/xml_writer_buf->content/xmlBufferContent(xml_writer_buf)/g' kvaMemoLibXML.cpp

This replaces direct struct field access with the appropriate accessor functions and removes the -Werror flag so that remaining warnings about virtual method hiding (-Werror=overloaded-virtual) do not block compilation. The library functions correctly after these changes.

@staticmethod
def kmfToKme(path_to_kmf: str, output_path: str = "./out/kme") -> None:
    from datetime import datetime

    # Resolve input path
    if os.path.isdir(path_to_kmf):
        kmf_path = os.path.join(path_to_kmf, "LOG00000.KMF")
    else:
        kmf_path = path_to_kmf

    if not os.path.exists(kmf_path):
        raise ValueError(f"KMF file not found: {kmf_path}")

    # Resolve output path
    if output_path.endswith(".kme50"):
        os.makedirs(os.path.dirname(output_path) or '.', exist_ok=True)
        out_path = output_path
    else:
        os.makedirs(output_path, exist_ok=True)
        date_str = datetime.now().strftime("%Y%m%d_%H%M%S")
        out_path = os.path.join(output_path, f"kmfToKme_output_{date_str}.kme50")

    print(f"Converting {kmf_path} -> {out_path}...")

    kmf = kvmlib.openKmf(kmf_path, kvmlib.Device.MHYDRA_EXT)
    kme = kvmlib.createKme(out_path, kvmlib.FileType.KME50)

    for log_file in kmf.log:
        for event in log_file:
            if isinstance(event, kvmlib.MessageEvent):
                kme.write_event(event)

    kme.close()
    print(f"Conversion done: {out_path}")

The kvmlib.Device.MHYDRA_EXT parameter specifies the device type. This is also the default value, and it applies to the Kvaser Memorator Pro 2xHS v2 used on the forumla. Older devices use a slightly different KMF structure.

Cache design and RAM estimation

KME files can be quite large, and therefore it makes no sense to load them without optimization. In this case, it was decided to create a cache during the first file read through scanning the entire file and then reading everything further out of the cache - overviews, queries with windows, graph data, etc.

The problem of a simple implementation lies in the possible cache size, which can easily exceed the amount of memory in the system. To avoid this problem, the cache size is estimated before loading, and it is checked whether it will fit into the system memory. If yes, then the cache will be loaded completely, otherwise, it will be downscaled.

The RAM estimate is calculated as follows:

1
2

frame_count = os.path.getsize(path) / 32
estimated_ram = frame_count * 90

Each MessageEvent is approximately 32 bytes on disk, giving an estimated frame count. Each decoded Python object occupies roughly 80–100 bytes in memory, so a median of 90 bytes is used. This is a rough approximation, but sufficient for the purpose.

def __estimate_fits_in_ram(self) -> bool:
    file_size = os.path.getsize(self.__path)
    frame_count = file_size / 32
    estimated_ram = frame_count * 90
    available_ram = psutil.virtual_memory().available
    fits = estimated_ram < available_ram * 0.75
    print(f"RAM estimate: {estimated_ram / 1e9:.2f}GB needed, "
            f"{available_ram / 1e9:.2f}GB available — "
            f"{'full cache' if fits else 'downsampled only'}")
    return fits

The _build_cache function uses this estimate to determine the sampling step. If a full cache fits in RAM, every frame is stored (step = 1). Otherwise, a step is calculated so that the total number of stored points stays within the available memory budget. Errors are always stored regardless of the step, since they are the highest-priority information in the log.

def _build_cache(self) -> None:
    if self._cache is not None:
        return

    fits_in_ram, available_ram = self.__estimate_fits_in_ram()
    self._downsampled_only = not fits_in_ram

    # Calculate max points we can store based on available RAM (75% headroom, 90 bytes/point)
    max_overview_points = int(available_ram * 0.75 / 90)
        print(f"Building cache (mode: {'full' if fits_in_ram else 'downsampled only'}, "
              f"max_points: {max_overview_points})...")

    # Calculate step for on-the-fly downsampling if needed
    if not fits_in_ram:
        file_size = os.path.getsize(self.__path)
        frame_count_estimate = max(1, int(file_size / 32))
        step = max(1, frame_count_estimate // max_overview_points)
    else:
        step = 1

    signals = {}
    errors = []
    duration = 0.0
    counter = 0

    for t, event in self.__iter_events():
        counter += 1
        duration = max(duration, t)

        parsed = self.__decoder.process_frame(event.id, event.data)
        if not parsed:
            continue

        is_error = any(v in ("ERROR_HIGH", "ERROR_LOW") for v in parsed.values())

        if not fits_in_ram and not is_error and counter % step != 0:
            continue

        for signal, value in parsed.items():
            if value in ("ERROR_HIGH", "ERROR_LOW"):
                errors.append({"t": t, "signal": signal, "type": value})
                continue
            if isinstance(value, (int, float)):
                signals.setdefault(signal, []).append([t, value])

    self._cache = {
        "duration": duration,
        "signals": signals,
        "errors": errors,
    }

    print(f"Cache built: {len(self._cache['signals'])} signals, "
          f"{len(errors)} errors, {duration:.1f}s duration")

def scan(self) -> dict:
    self._build_cache()
    return {
        "duration": self._cache["duration"],
        "errors":   self._cache["errors"],
        "signals":  list(self._cache["signals"].keys()),
        "downsampled_only": self._downsampled_only
    }

read_window

The read_window method returns all decoded signal values within a given time range. When a full cache is available, this is served entirely from RAM. When the cache is downsampled, it falls back to reading from disk at full resolution for that specific window, since the downsampled cache would not have sufficient point density for a narrow time range.

def read_window(self, t_start: float, t_end: float) -> dict:
    self._build_cache()
 
    if self._downsampled_only:
        # Go back to disk for full resolution window
        print(f"read_window: disk read [{t_start:.2f}s -> {t_end:.2f}s]")
        result = {}
        for t, event in self.__iter_events():
            if t < t_start:
                continue
            if t > t_end:
                break
            parsed = self.__decoder.process_frame(event.id, event.data)
            if not parsed:
                continue
            for signal, value in parsed.items():
                if isinstance(value, (int, float)):
                    result.setdefault(signal, []).append([t, value])
        return result
 
    # Full cache — instant
    result = {}
    for signal, points in self._cache["signals"].items():
        window = [[t, v] for t, v in points if t_start <= t <= t_end]
        if window:
            result[signal] = window
    return result

get_overview

The get_overview function gives downsampled data for rendering the graph. The rendering of all points in a big log file would not be possible; hence, this function uses index-based downsampling by saving each nth point where n is selected to ensure that the maximum number of points is not exceeded. In contrast to the _build_cache function, the maximum number of points is given as a parameter (the default value is 1000), enabling the Electron frontend to modify this value depending on screen size and zoom level.

def get_overview(self, max_points: int = 1000, t_start=None, t_end=None) -> dict:
    self._build_cache()
 
    if self._downsampled_only and t_start is not None and t_end is not None:
        # Cache is downsampled over full session — a sub-window would have too few
        # points to be useful. Go to disk for full resolution then downsample.
        print(f"get_overview: downsampled mode + time window, disk read [{t_start:.2f}s -> {t_end:.2f}s]")
        source = self.read_window(t_start, t_end)
    elif t_start is not None and t_end is not None:
        # Full cache — query RAM for window
        source = self.read_window(t_start, t_end)
    else:
        source = self._cache["signals"]
 
    overview = {}
    for signal, points in source.items():
        if len(points) <= max_points:
            overview[signal] = points
            continue
        step = len(points) / max_points
        overview[signal] = [points[int(i * step)] for i in range(max_points)]
 
    return overview

Exporting

The KmeReader class supports exporting to CSV and ASC formats, which is useful when more detailed inspection is needed outside of the telemetry application — for example, opening a log in BusMaster, which supports the ASC format.

CSV

CSV export can be optimized based on whether a full cache is available. If it is, the export writes directly from memory without re-reading the file. If the cache is downsampled, the method streams directly from the KME file to avoid accumulating additional data in RAM.

def export_CSV(self, output_path: str = "./") -> None:
    import csv

    path = self.__resolve_output_path(output_path, "csv")
    self._build_cache()

    print(f"Exporting CSV to {path}...")

    if not self._downsampled_only:
         # Full cache available — write directly without touching the file
        all_timestamps = sorted(set(
            t
            for points in self._cache["signals"].values()
            for t, _ in points
        ))

        signal_names = list(self._cache["signals"].keys())
        lookup = {signal: {t: v for t, v in points}
                for signal, points in self._cache["signals"].items()}

        with open(path, 'w', newline='') as f:
            writer = csv.writer(f)
            writer.writerow(["timestamp"] + signal_names)
            for t in all_timestamps:
                row = [f"{t:.6f}"]
                for signal in signal_names:
                    row.append(lookup[signal].get(t, ""))
                writer.writerow(row)
    else:
        # Downsampled only — stream from file directly to CSV, no RAM accumulation
        print("export_CSV: downsampled cache, streaming file to CSV...")

        signal_names = list(self._cache["signals"].keys())

        with open(path, 'w', newline='') as f:
            writer = csv.writer(f)
            writer.writerow(["timestamp"] + signal_names)

            latest = {s: "" for s in signal_names}
            for t, event in self.__iter_events():
                parsed = self.__decoder.process_frame(event.id, event.data)
                if not parsed:
                    continue
                updated = False
                for signal, value in parsed.items():
                    if signal in latest and isinstance(value, (int, float)):
                        latest[signal] = f"{value}"
                        updated = True
                if updated:
                    row = [f"{t:.6f}"] + [latest[s] for s in signal_names]
                    writer.writerow(row)

    print(f"CSV export done: {path}")

def export_ASC(self, output_path: str = "./") -> None:
    from datetime import datetime

    path = self.__resolve_output_path(output_path, "asc")
    self._build_cache()

    print(f"Exporting ASC to {path}...")

    with open(path, 'w') as f:
        f.write(f"date {datetime.now().strftime('%a %b %d %H:%M:%S %Y')}\n")
        f.write("base hex  timestamps absolute\n")
        f.write("no internal events logged\n")
        f.write("// Generated from: " + self.__path + "\n")
        f.write("Begin Triggerblock\n")

        with kvmlib.openKme(self.__path) as kme:
            for event in kme:
                if not isinstance(event, kvmlib.MessageEvent):
                    continue
                t = event.timeStamp / 1e9
                id_hex = f"{event.id:X}"
                data_hex = ' '.join(f"{b:02X}" for b in event.data)
                f.write(f"   {t:.6f} {event.channel + 1}  {id_hex:<15} Rx   d {event.dlc}  {data_hex}\n")

        f.write("End TriggerBlock\n")

    print(f"ASC export done: {path}")

Conclusion

The KmeReader class represents a complete processing pipeline for handling Kvaser Memorator log files within our Python-based telemetry application. This includes reading raw KMF files from SD card, converting them into self-sufficient KME format, memory-efficient caching with automatic switching to downsampling when needed, querying data in windows, generating graph-friendly overview of the file, as well as exporting data in CSV and ASC formats.

The problem we faced during design was the need to handle files that might be larger than available memory. The estimation-based approach, where the decision is made on the fly whether to cache the whole file or only a downsampled version, allows us to keep everything working for any size of files without any manual intervention. Error events are always cached in full resolution no matter what, as they represent the most important information in post-flight analysis.

This class is included in our WebSocket server codebase and used by the telemetry application frontend written using Electron framework, which relies on scan, get_overview, and read_window functions.
